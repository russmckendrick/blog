# AGENTS.md

## Always Relevant Rules

- Prefer `pnpm` for all package and script commands.
- Run `npx astro check` after code, component, schema, or content-model changes; add `pnpm run astro -- sync` when content collections or the schema in `src/content.config.ts` change.
- Keep code style consistent with the repo: 2-space indent, no semicolons, PascalCase components, kebab-case route files.
- Blog posts belong in `src/content/blog/` as `YYYY-MM-DD-slug.mdx`.
- Tunes posts belong in `src/content/tunes/`, usually as directory-based entries with `index.mdx`. Tunes use flat `heroImage:` only - the `cover` object is no longer accepted.
- Glossary entries live in `src/content/glossary/{term-slug}.mdx`; books live in `src/content/books/{book-slug}.mdx` (each book becomes `/books/{slug}/`).
- Use `sanitize-html` for HTML sanitization. Do not add regex-based sanitization.
- Update every affected doc in `docs/` in the same change as the code, checking the index in `docs/README.md`. This applies to every run, not just when you already know a doc covers the topic - if your change introduces, removes, or alters behaviour any doc references, update that doc.

## High-Value Project Context

- See `DESIGN.md` for design tokens and component conventions before generating UI.
- Image delivery is runtime-based through Cloudflare Image Transformations, not build-time processing. Reuse helpers in `src/utils/cloudflare-images.ts`.
- Link preview images are cached into `public/assets/link-previews/` by `scripts/cache-link-preview-images.js`.
- `src/data/hero-colors.json` is still generated by `scripts/extract-hero-colors.js` during prebuild, but no page renders gradient headers from it anymore - tag/year hubs use flat paper backgrounds with hairline rules.
- The header logo (`src/components/layout/Logo.astro`) renders wordmark outlines from `src/data/logo-lockup.json`; that file and `public/favicon.svg` are generated by `scripts/generate-logo.js` (`pnpm run generate-logo`) - never hand-edit them, and Poppins is deliberately not loaded as a webfont.
- MDX embeds are registered globally through `mdx-components.ts`; new embed components also need wiring in the relevant Astro page/template files.

## When a Full Rebuild Is Needed

- `pnpm run build` only for what the static output bakes in - routing, the sitemap, Pagefind indexing, `astro.config.mjs`. Pages, components, styles, and content all re-render on request under `pnpm run dev`.
- `scripts/` edits need no rebuild - they are standalone tools whose output is committed. The exceptions are the five wired into the build: `extract-hero-colors.js`, `cache-link-preview-images.js`, `fetch-reading-list.js`, and `build-tunes-index.js` (via `prebuild`), plus `generate-llms-markdown.js` (after `astro build`); edits to those land on the next build. One consequence worth knowing: the per-post `index.md` twins and `llms.txt` exist only in built output, so they 404 under `pnpm run dev` - check them with `pnpm run build && pnpm run preview`.
- OpenGraph cards (`src/components/OpenGraph/`, the `*-og.png.ts` endpoints under `src/pages/`) need no rebuild to iterate - `pnpm run dev` regenerates each per request, so just reload the `.png` URL. They use `getStaticPaths()` on a fully static site, so shipping new cards still needs a build.

## Using graphify

- The graph is already built (`graphify-out/`, gitignored). For structural questions - what renders X, what calls Y, how data reaches a page - run `graphify query "<question>"` before grep or Explore; it answers in one call instead of reading file by file.
- It indexes prose as well as code (`docs/`, `DESIGN.md`), so it also answers "where is this documented?".
- Never rebuild just to answer a question. Rebuild only when structure moves - new pages, new collections, a reorganised `src/` - and pass `--update`. The dated directories in `graphify-out/` show the last build.
- Never commit `graphify-out/` and never hand-edit `graph.json`, `manifest.json`, or `GRAPH_REPORT.md` - all are generated.
